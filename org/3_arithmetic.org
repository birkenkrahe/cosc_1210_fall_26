* Arithmethic operators I

"Arithmetic" from Greek ἀριθμητική, the art of working with numbers
(ἀριθμός).

Working with numbers requires ways of combining them. Another way to
look at this is by imagining a space of numbers: Operators are a way
of getting around that space from one number to another.

The basic ways of combining numbers are:
1. Addition
2. Subtraction
3. Multiplication
4. Division

* Expressions

- Let's look at addition, subtraction, multiplication and division.

- An *expression* is any combination of numbers and these operators.

- There are only two operations here:
  1) Subtraction is addition with negative numbers: 2-3 is 2 + (-3)
  2) Division is multiplication with fractions: 10/2 is 10 * 1/2

- The machine exploits symmetries to reduce the number of operations:
  1) for addition/subtraction that's the symmetry around zero (0 is
     the identity element: a + 0 = a)
  2) for multiplication/division that's the symmetry around one (1 is
     the identity element: a * 1 = a)

- The machine cannot look at a formula as a whole, e.g. 30 + 12

** Operator precedence

- When it encounters several operators and values, it applies operator
  precedence rules ("PEMDAS"):
  #+begin_src python :results output :exports both :session *Python* :python python3
    print(3 * 5 - 5)    # from left to right, multiplication first: 15 - 5
    print(5 - 5 * 3)    # from left to right, multiplication first: 5 - 15
    print( (5 - 5) * 3) # from left to right, parentheses first: 0 * 3
    print( 5 - (5 * 3))  # from left to right, 5 - 15
  #+end_src

  #+RESULTS:
  : 10
  : -10
  : 0
  : -10

** Exponentiation and number representation

- Exponentiation is multiplication of the same number:
  #+begin_src python :results output :exports both :session *Python* :python python3
    print(2**3)
    print(2 * 2 * 2)
  #+end_src

  #+RESULTS:
  : 8
  : 8

- Exponentiation can be tricky if the exponent is not an integer:
  #+begin_src python :results output :exports both :session *Python* :python python3
    print(2**0.5) # square root of 2: where f(x)=x**2-2=0 (two solutions)
  #+end_src

  #+RESULTS:
  : 1.4142135623730951

- Digital numbers aren't really numbers:
  #+begin_src python :results output :exports both :session *Python* :python python3 
    print(f"{2**0.5:.2f}")  # truncated for display
  #+end_src  

  #+RESULTS:
  : 1.41

- So which number is it?
  #+begin_quote
  Neither. What's stored is an IEEE double (standard), 15-17 digits of
  precision. The full decimal form has 52 places:
  1.4142135623730951454746218587388284504413604736328125
  #+end_quote

- What ~print~ shows and why:
  #+begin_quote
  The problem is that binary fractions (the way the computer stores
  them) do not cleanly map to decimal fractions. The ~print~ of a float
  shows the shortest decimal string that round-trips: the fewest
  digits that, when parsed back, land on that exact double. For this
  value, that's 1.4142135623730951 (17 digits).
  #+end_quote

- Code example:
  #+begin_src python :results output :exports both :session *Python* :python python3 
    import math
    x = math.sqrt(2)
    x
    1.4142135623730951
    print(float("1.4142135623730951") == x)  # now drop one digit 
    print(float("1.414213562373095") == x)   # different double
  #+end_src

  #+RESULTS:
  : True
  : False

- Square root visualization:
  #+begin_src python :file ../img/squareRoot.png :results file graphics output :exports both :session *Python* :python python3
    import matplotlib.pyplot as plt

    def f(x):
        return x**2 - 2

    # x and y values as list comprehensions
    xs = [i / 100 for i in range(0,201)] # 0.00, 0.01...2.00
    ys = [f(x) for x in xs]

    # plot
    plt.plot(xs,ys,label="f(x) = x**2 - 2")
    plt.axhline(0,color="grey",linewidth=0.8) # horizontal line y = 0
    plt.axvline(2**0.5,color="red",linestyle="--",
                label="x = 2**0.5 = 1.414...")
    plt.plot(2**0.5, f(2**0.5),"ro") # the crossing point
    plt.xlabel("x"); plt.ylabel("f(x)")
    plt.legend()
    plt.savefig("../img/squareRoot.png")
  #+end_src
