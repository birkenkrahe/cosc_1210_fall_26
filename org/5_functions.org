* Why functions?

- A function *names* a group of statements, so the program reads more
  like a description of what it does.
- The code appears *once*. Fix a bug or change the wording in one
  place, and every call gets it.
- You can build and test the pieces *separately*, then assemble them.
- A good function is *reusable* in the next program.

* Anatomy of a function

A function groups statements under a name so you can run them again by
calling the name. The smallest useful one takes no input:

#+begin_src python :results output :exports both :session *Python* :python python3
  def welcome():
      print("Welcome to COSC 1210.")
      print("Today's topic: functions.")

  welcome()
#+end_src

#+RESULTS:
: Welcome to COSC 1210.
: Today's topic: functions.

- ~def~ is the keyword that starts a *definition*.
- ~welcome~ is the name - any legal variable name works.
- The empty ~()~ mean "no input".
- The header ends with a colon ~:~; the *body* is indented (four
  spaces).
- Nothing happens until you *call* it: ~welcome()~.

Defining a function creates a value, like a number or a string - its
type is ~function~:

#+begin_src python :results output :exports both :session *Python* :python python3
  print(type(welcome))
#+end_src

#+RESULTS:
: <class 'function'>

* Parameters and arguments

** One parameter

To pass input in, put a *parameter* name in the parentheses:

#+begin_src python :results output :exports both :session *Python* :python python3
  def greet(name):
      print("Hello, " + name + "!")

  greet("Jim")
  greet("Joe")
#+end_src

#+RESULTS:
: Hello, Jim!
: Hello, Joe!

- ~name~ is a *parameter* - it belongs to the definition.
- ~"Jim"~ is an *argument* - it belongs to the call.
- Calling ~greet("Jim")~ is the same as doing ~name = "Jim"~ and then
  running the body:

#+begin_src python :results output :exports both :session *Python* :python python3
  name = "Jim"
  print("Hello, " + name + "!")
#+end_src

#+RESULTS:
: Hello, Jim!

An argument can be a variable, not just a literal:

#+begin_src python :results output :exports both :session *Python* :python python3
  student = "Joe"
  greet(student)
#+end_src

#+RESULTS:
: Hello, Joe!

Parameter names follow the same rules as any other Python name: no
reserved words, no spaces, and so on.

** Two parameters

Two parameters, separated by commas (this time with an f-string):

#+begin_src python :results output :exports both :session *Python* :python python3
  def greet_course(name, course):
      print(f"Hello, {name}, welcome to {course}.")

  greet_course("Jim", "COSC 1210")
#+end_src

#+RESULTS:
: Hello, Jim, welcome to COSC 1210.

Every definition has the same parts:

| Part       | In ~greet_course~                    |
|------------+------------------------------------|
| keyword    | ~def~                                |
| name       | ~greet_course~                       |
| parameters | ~name~, ~course~                       |
| colon      | ~:~                                  |
| body       | the indented ~print(...)~            |
| call       | ~greet_course("Jim", "COSC 1210")~   |
| arguments  | ~"Jim"~, ~"COSC 1210"~                 |

*Parameters* live in the definition; *arguments* live in the call.

Parameters do not have to be strings - here both are numbers:

#+begin_src python :results output :exports both :session *Python* :python python3
  def add(a, b):
      print(a + b)

  add(2, 2)
#+end_src

#+RESULTS:
: 4

** Default parameters

You've seen this in the Python documentation for built-in functions:
some parameters are "positional" (Python expects them only there),
others are "named":

Example:
#+begin_src python :results output :exports both :session *Python* :python python3
  help(round)
#+end_src

#+RESULTS:
: Help on built-in function round in module builtins:
:
: round(number, ndigits=None)
:     Round a number to a given precision in decimal digits.
:
:     The return value is an integer if ndigits is omitted or None.  Otherwise
:     the return value has the same type as the number.  ndigits may be negative.

The ~number~ parameter is *positional*, so that when you type =round(2.55)=
it is recognized: =number = 2.55=.

The ~ndigits~ parameter for the number of digits to be kept after the
decimal point is *named*.

Try it: give only ~number~ and ~ndigits~ falls back to its default
(~None~), so you get a whole number back; give ~ndigits~ too - by
position or by name - and you get decimal places:

#+begin_src python :results output :exports both :session *Python* :python python3
  print(round(3.1459))
  print(round(3.1459, 2))
  print(round(3.1459, ndigits=2))
#+end_src

#+RESULTS:
: 3
: 3.15
: 3.15

We could also create a greeting function with a named parameter. Then
it could be called either with or without an argument:
#+begin_src python :results output :exports both :session *Python* :python python3
  def hello(name="there"):
      print(f"Hello, {name}!")

  hello()
  hello("Jane")
#+end_src

#+RESULTS:
: Hello, there!
: Hello, Jane!

* Documenting a function

A string on the first line of the body is a *docstring* - a note about
what the function does. ~help()~ shows it:

#+begin_src python :results output :exports both :session *Python* :python python3
  def greet(name):
      "Print a friendly hello for the given name."
      print("Hello, " + name + "!")

  help(greet)
#+end_src

#+RESULTS:
: Help on function greet in module __main__:
:
: greet(name)
:     Print a friendly hello for the given name.

When a function has several arguments, arguments whose meaning is not
obvious, or output that needs explaining, put that in the docstring too
- not just a one-line summary.

Compare =help(round)= again, this time the last two lines: they say
what the function *gives back* and how its type depends on the input.
#+begin_src python :results output :exports both :session *Python* :python python3
  help(round)
#+end_src

#+RESULTS:
: Help on built-in function round in module builtins:
:
: round(number, ndigits=None)
:     Round a number to a given precision in decimal digits.
:
:     The return value is an integer if ndigits is omitted or None.  Otherwise
:     the return value has the same type as the number.  ndigits may be negative.

Here is the same idea for a user-defined function. =fahrenheit= takes a
temperature and prints it in another unit - and =celsius= alone does
not tell you whether the *input* or the *output* is in Celsius, so the
docstring has to.

#+begin_src python :results output :exports both :session *Python* :python python3
  def fahrenheit(celsius):
      """Print a Celsius temperature converted to Fahrenheit.

      celsius -- a temperature in degrees Celsius (a number)
      Prints the same temperature in degrees Fahrenheit; returns nothing.
      """
      print(celsius * 9 / 5 + 32)

  fahrenheit(100)
  help(fahrenheit)
#+end_src

#+RESULTS:
: 212.0
: Help on function fahrenheit in module __main__:
:
: fahrenheit(celsius)
:     Print a Celsius temperature converted to Fahrenheit.
:
:     celsius -- a temperature in degrees Celsius (a number)
:     Prints the same temperature in degrees Fahrenheit; returns nothing.

The docstring has three parts, like the ones from ~help(round)~:
- a one-line *summary* of what the function does;
- one line per *parameter*, saying what it stands for and its type;
- a line about the *output* - here, that it prints and hands nothing
  back.

* PRACTICE design a docstring

Add a docstring to each function below that names its arguments and
says what it does with them, then test both with ~help~:

#+begin_src python :results output :exports both :session *Python* :python python3
  def hypotenuse(a, b):

#+end_src
