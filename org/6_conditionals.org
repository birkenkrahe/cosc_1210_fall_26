** DONE Integer division and modulus

The countdown clock in mission control shows minutes and seconds, but
the rocket only knows seconds. Two operators turn one into the other:

- ~//~ (floor division) gives the whole number of times one number
  fits into another
- ~%~ (modulus) gives what is left over

#+begin_src python :results output :exports both :session *Python* :python python3
  print(125 // 60)   # whole minutes in 125 seconds
  print(125 % 60)    # seconds left over
#+end_src

#+RESULTS:
: 2
: 5

You met ~divmod~ earlier - it does both at once:

#+begin_src python :results output :exports both :session *Python* :python python3
  minutes, secs = divmod(125, 60)
  print(minutes, secs)
#+end_src

#+RESULTS:
: 2 5

~divmod~ hands back two values, and the two names on the left of the ~=~
receive one each (this is also called a ~tuple~).

Put it in a function. The format specifier ~:02d~ pads a whole number
with a leading zero to two digits (compare ~:.2f~ for decimals):

#+begin_src python :results output :exports both :session *Python* :python python3
  print(f"{5:02d}")
  print(f"{45:02d}")
#+end_src

#+RESULTS:
: 05
: 45

#+begin_src python :results output :exports both :session *Python* :python python3
  def clock(seconds):
      """Print a number of seconds as a T-minus clock, e.g. T-2:05."""
      minutes = seconds // 60
      secs = seconds % 60
      print(f"T-{minutes}:{secs:02d}")

  clock(125)
  clock(59)
  clock(600)
#+end_src

#+RESULTS:
: T-2:05
: T-0:59
: T-10:00

** DONE Boolean expressions

A *boolean expression* is an expression that is either ~True~ or
~False~. The comparison operators produce them:

| Operator | Means                    |
|----------+--------------------------|
| ~==~       | equal to                 |
| ~!=~       | not equal to             |
| ~<~ ~>~      | less than, greater than  |
| ~<=~ ~>=~    | at most, at least        |

#+begin_src python :results output :exports both :session *Python* :python python3
  print(2 + 2 == 4)
  print(3 != 3)
  print(7 > 10)
  print(7 <= 7)
  print("GO" == "GO")
#+end_src

#+RESULTS:
: True
: False
: False
: True
: True

Watch out: ~=~ *assigns*, ~==~ *compares*. Mixing them up is a classic
mistake - Python usually catches it:

#+begin_src python :results none :session *Python* :python python3
  fuel = 96
  if fuel = 90:
      print("exactly 90")
#+end_src

#+begin_example
SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?
#+end_example

** DONE Logical operators

Three operators combine booleans:

- ~A and B~ is ~True~ only if both are
- ~A or B~ is ~True~ if at least one is
- ~not A~ is the opposite of ~A~

#+begin_src python :results output :exports both :session *Python* :python python3
  print(fuel >= 90 and wind < 25)   # GO only if BOTH are fine
  print(fuel >= 90 or wind < 5)     # at least one is fine
  print(not wind < 25)              # the opposite
#+end_src

#+RESULTS:
: True
: True
: False

All four combinations at a glance:

#+begin_src python :results output :exports both :session *Python* :python python3

#+end_src

#+RESULTS:
: True and True = True | True or True = True
: True and False = False | True or False = True
: False and True = False | False or True = True
: False and False = False | False or False = False

** The if statement

A conditional statement runs code only when a condition is ~True~:

#+begin_src python :results output :exports both :session *Python* :python python3
  fuel = 96
  if fuel >= 90:
      print("Fuel: GO")
#+end_src

#+RESULTS:
: Fuel: GO

- The first line is the *header*; it ends with a colon.
- The indented lines below are the *body*. The body runs only if the
  condition is ~True~.
- The first unindented line is not part of the ~if~.

Change the reading and run it again - now nothing is printed for the
fuel, but the last line still runs:

#+begin_src python :results output :exports both :session *Python* :python python3
  fuel = 85
  if fuel >= 90:
      print("Fuel: GO")
      print("(poll finished)")
#+end_src

#+RESULTS:
: (poll finished)

Forget the colon and Python refuses to run the code at all - the same
kind of error you found in the debug-the-report practice:

#+begin_src python :results none :session *Python* :python python3

  print("Fuel: GO")
#+end_src

** The else clause

Silence is not an answer. Mission control needs *NO-GO* when the
condition is ~False~:

#+begin_src python :results output :exports both :session *Python* :python python3
  fuel = 85
  if fuel >= 90:
      print("Fuel: GO")
  else:
      print("Fuel: NO-GO")
#+end_src

#+RESULTS:
: Fuel: NO-GO

Exactly one of the two bodies runs. Now poll three stations, the
copy-and-paste way ("guidance" systems include the onboard computer
and sensors that steer the rocket along its trajectory):

#+begin_src python :results output :exports both :session *Python* :python python3
  fuel, engines, guidance = 96, 88, 100     # readings in percent

  if fuel >= 90:
      print("Fuel: GO")
  else:
      print("Fuel: NO-GO")

  if engines >= 95:
      print("Engines: GO")
  else:
      print("Engines: NO-GO")

  if guidance >= 99:
      print("Guidance: GO")
  else:
      print("Guidance: NO-GO")
#+end_src

#+RESULTS:
: Fuel: GO
: Engines: NO-GO
: Guidance: GO

Can we replace this with one statement?
#+begin_src python :results output :exports both :session *Python* :python python3
  if fuel >= 90 and engines >= 95 and guidance >= 99:
      print("GO")
  else:
      print("NO-GO")
#+end_src

#+RESULTS:
: NO-GO

Three copies of the same steps, differing only in the values: the
station name, the reading and the minimum. Whenever the steps stay the
same and only *values* change, you can *refactor* - reorganize working
code without changing what it does - into one function with
parameters:

#+begin_src python :results output :exports both :session *Python* :python python3
  def go_nogo(system, reading, minimum):
      """Print GO if the reading reaches the minimum, else NO-GO.

      system  -- name of the station (string)
      reading -- current value (number)
      minimum -- lowest acceptable value (number)
      Prints one line; returns nothing.
      """
      if reading >= minimum:
          print(f"{system}: GO")
      else:
          print(f"{system}: NO-GO")

  go_nogo("Fuel", 96, 90)
  go_nogo("Engines", 88, 95)
  go_nogo("Guidance", 100, 99)
#+end_src

#+RESULTS:
: Fuel: GO
: Engines: NO-GO
: Guidance: GO

Same output, and a fourth station now costs one line. Fix a bug in the
poll once, and every station gets the fix.

** Value change or step change?

Whenever you see code that looks repeated, you have to decide: one
function with parameters, or several separate functions? The rule that
decides it is one question:

*The design rule:* when you decide between one parameterized function
and several functions, ask: does the variation between cases change a
*value*, or does it change the *steps*? Here only values change - one
function. (More on the other case in session 2.)

What does that mean? Look at the three copies again. Put them side by
side and mark what is *the same* in all three, and what *differs*:

| What happens       | Fuel           | Engines        | Guidance       |
|--------------------+----------------+----------------+----------------|
| Steps (all three)  | compare, print | compare, print | compare, print |
| Value: the name    | ~"Fuel"~         | ~"Engines"~      | ~"Guidance"~     |
| Value: the reading | ~fuel~ (96)      | ~engines~ (88)   | ~guidance~ (100) |
| Value: the minimum | ~90~             | ~95~             | ~99~             |

#+begin_example
| What happens       | Fuel           | Engines        | Guidance         |
|--------------------|----------------|----------------|------------------|
| Steps (all three)  | compare, print | compare, print | compare, print   |
| Value: the name    | `"Fuel"`       | `"Engines"`    | `"Guidance"`     |
| Value: the reading | `fuel` (96)    | `engines` (88) | `guidance` (100) |
| Value: the minimum | `90`           | `95`           | `99`             |
#+end_example

The first row is identical in every column: that is the *steps* - the
things the code does. The other three rows differ - those are the
*values* the steps work on. Values can be turned into *parameters*
(~system~, ~reading~, ~minimum~), and the steps are written once, in the
function body. That is all ~go_nogo~ does.

A test that works for any code: describe what the copies do in *one
sentence with blanks*.

- "Compare a ~___~ reading with a minimum of ~___~ and print
  ~___: GO~ or ~___: NO-GO~." Every blank is a value - one function
  with three parameters.

If you cannot write such a sentence - if the description has to
change, not just its blanks - the steps differ, and you need
separate functions.

*Another example with values:* you have already written ~discount~.
Three shop items, three prices, three percentages - the steps (take the

The sentence with blanks: "Take ~___~ percent off the price ~___~ and

*An example where the steps change:* converting a temperature. Celsius
to Fahrenheit multiplies first and then adds; Fahrenheit to Celsius
subtracts first and then multiplies. Both take one number and print one
number, so they look alike - but the *calculation* differs, and no
values can express that:

#+begin_src python :results output :exports both :session *Python* :python python3
  def to_fahrenheit(celsius):
      """Print a Celsius temperature in Fahrenheit."""
      print(celsius * 9 / 5 + 32)

  def to_celsius(fahrenheit):
      """Print a Fahrenheit temperature in Celsius."""
      print((fahrenheit - 32) * 5 / 9)

  to_fahrenheit(100)
  to_celsius(212)
#+end_src

#+RESULTS:
: 212.0
: 100.0

You could squeeze both into one function ~convert(number, direction)~
with an ~if~ on ~direction~. But then the two calculations are simply
sitting side by side in one body, sharing nothing, and the ~if~ only
decides which of them to run. Two clearly named functions are easier to
read, test and fix. We will see this problem again in session 2.

Now you decide. For each pair, is the difference a *value* or the
*steps*?

1. Three stations checking a reading against a minimum.
2. Printing =Hello, Ada!= and printing =Hello, Bo!=.
3. Adding two numbers and multiplying two numbers.
4. Printing a row of 3 stars and printing a row of 5 stars.

#+begin_quote
1) Values (the reading and the minimum): one function, as in ~go_nogo~.
2) A value (the name): one function ~hello(name)~.
3) The steps (~+~ versus ~*~): two functions.
4) A value (the number of stars): one function with a parameter.
#+end_quote

2. The fuel check fits the sentence "Compare a ~___~ reading with a
   minimum of ~___~ and print GO or NO-GO" - that is ~go_nogo~. The
   temperature check does not: it needs *two* limits and two

#+begin_src python :results output :exports both :session *Python* :python python3
  def go_nogo_range(system, reading, low, high):
      """Print GO if the reading is between low and high, else NO-GO.

      system  -- name of the station (string)
      reading -- current value (number)
      low     -- lowest acceptable value (number)
      high    -- highest acceptable value (number)
      Prints one line; returns nothing.
      """
      if low <= reading <= high:
          print(f"{system}: GO")
      else:
          print(f"{system}: NO-GO")

  go_nogo("Fuel", 96, 90)
  go_nogo_range("Temperature", 20, 0, 35)
  go_nogo_range("Temperature", 40, 0, 35)
