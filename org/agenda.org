   #+begin_quote

   #+end_quote

2) What are the three parts of a computer and what distinguishes them?
   #+begin_quote
   - The CPU is super-fast: access latency is about 0.3 ns (billionth)
   - The RAM is fast: access latency is about 100 ns
   - The NVM is super-slow: access latency of a hard disk is 10 ms

   If one CPU cycle was 1 second, then the RAM is a coffee break, a
   SSD is a full day, and a HDD is a year.
   #+end_quote

1) ~divmod~ is a function that combines integer division and modulo
   operation: =divmod(a,b) = (a // b, a % b)=

   What is the result of =divmod(10,3)=?
   #+begin_src python :results output :exports both :session *Python* :python python3 
     print(divmod(10,3)) # 10 = 3 * 3 + 1
   #+end_src

   #+RESULTS:
   : (3, 1)

2) How would you convert 500 days to whole days and leftover hours?
   #+begin_src python :results output :exports both :session *Python* :python python3 
     print(divmod(500,24)) # how many times does 24 fit in 500
     print(f"500 days are {divmod(500,24)[0]} whole days \
     and {divmod(500,24)[1]} hours.")
   #+end_src

   #+RESULTS:
   : (20, 20)
   : 500 days are 20 whole days and 20 hours.

3) What do you need to remember about using ~round~ on decimals ending
   in 5?
   #+begin_quote
   ~round~ works from the actual stored value, not the decimal
   literal. A decimal ending in 5 is almost never a perfect tie in
   binary.
   #+end_quote
   #+begin_src python :results output :exports both :session *Python* :python python3 
     print(round(3.675,2))
   #+end_src

   #+RESULTS:
   : 3.67

4) What do you get when you run =print("Spam") * 5= ?
   #+begin_quote
   ="Spam"= because the machine executes from the left, and then you get
   a ~TypeError~ because the operands =print("Spam")= and =5=, cannot be
   multiplied (=5= is an integer, and =print("Spam")= returns "nothing"
   aka ~None~ - it only does something, namely print.
   #+end_quote

5) What's "XOR" stand for?
   #+begin_quote
     XOR is a logical operator. It is ~True~ only if its two operands
     have different truth (aka boolean) values:

     | p     | q     | p XOR q | Example                   |
     |-------+-------+---------+---------------------------|
     | True  | True  | False   | N is even and odd         |
     | True  | False | True    | N = 4: even, not odd      |
     | False | True  | True    | N = 7: odd, not even      |
     | False | False | False   | N is neither even nor odd |

     In Python, the caret (~^~) is the XOR operator for binary values.
   #+end_quote
   #+begin_src python :results output :exports both :session *Python* :python python3 
     n = 5
     print((n % 2 == 0) ^ (n % 2 == 1)) # always True for any integer n
                                        # (tautology)
   #+end_src

** Review: strings, values, types, and errors

From week 2, part 2 (string functions onward) - the ground quiz 2 covers.

1) Strings are called *immutable*. What does that mean, and what do the
   string methods ~upper~ and ~lower~ actually do to a string?
   #+begin_quote
   Immutable = you cannot change a character inside an existing
   string; the string object itself never changes. ~"hello".upper()~
   does not touch ="hello"= - it builds and returns a *new* string
   ="HELLO"=.
   #+end_quote

2) Why is ~len("hello")~ written differently from ~"hello".upper()~?
   #+begin_quote
   ~len~ is a *built-in function*: the string goes inside its parentheses
   as an *argument*. ~upper~ is a *string method*: it belongs to the string
   and you reach it with the *dot operator*, with empty parentheses.
   You can also call ~len~ on other other data structures, e.g. a list.
   #+end_quote
   #+begin_src python :results output :exports both :session *Python* :python python3
     print(len("hello"))      # function - argument in ()
     print("hello".upper())   # method - reached with the dot
     print(len(range(0,9)));  # calling len() on a range of numbers
     print(type(range(0,9)))
     print(len([100,"hello", [3.14,2.71]])) # calling len() on a list
   #+end_src

3) In ="Spam, " * 5 + "and Spam!"=, does the ~*~ or the ~+~ happen
   first, and what is the result?
   #+begin_src python :results output :exports both :session *Python* :python python3
     print("Spam, " * 5 + "and Spam!")   # * binds tighter than +
   #+end_src

4) What happens when you run =print(2 + " Spam " * 5)=?
   #+begin_quote
   A ~TypeError~. The ~*~ is fine (=str * int= repeats the string), but
   then ~+~ needs a string on both sides and =2= is an integer - the
   same reason ="Spam" + 5= fails.
   #+end_quote
   #+begin_src python :results output :exports both :session *Python* :python python3 
     print(str(2) + " Spam " * 5)
   #+end_src
   
5) Python is *dynamically typed*, and every value has a type. Name the
   four basic types, with one value of each.
   #+begin_src python :results output :exports both :session *Python* :python python3
     print(type(2))        # int   - whole number
     print(type(33.3))     # float - number with a decimal point
     print(type("hello"))  # str   - text
     print(type(True))     # bool  - True / False
   #+end_src

6) What does =int(33.9)= give? And =int(-33.9)=? Is that rounding?
   #+begin_src python :results output :exports both :session *Python* :python python3
     print(int(33.9))   # 33  - drops the fraction, does NOT round
     print(int(-33.9))  # -33 - truncates towards zero
   #+end_src

7) =int("444")= works but =int("hello")= does not. What is the
   difference?
   #+begin_quote
   =int("444")= returns =444=, an ~int~. =int("hello")= raises a ~ValueError~:
   the argument is the right *type* (a string) but its *value* cannot be
   read as a decimal number.
   #+end_quote

8) =print(str(33))= and =print(33)= put the same thing on screen. So
   what did ~str~ actually change?
   #+begin_quote
   Nothing you can see - ~str~ converts the *type* from ~int~ to ~str~.
   The type is not visible in the output; you check it with ~type~.
   #+end_quote
   #+begin_src python :results output :exports both :session *Python* :python python3
     print(str(33))         # looks like 33
     print(type(str(33)))   # ...but it is a string now
     print(type(33))        # the original is still an int
   #+end_src

   #+RESULTS:
   : 33
   : <class 'str'>
   : <class 'int'>

9) A rule of thumb: when do you get a ~ValueError~ and when a
   ~TypeError~? Could you come up with an example for each?
   #+begin_quote
   Wrong *type* for the operation -> ~TypeError~. Right type but an
   unusable *value* -> ~ValueError~.
   #+end_quote
   #+begin_src python :results none :exports both :session *Python* :python python3 
     print(2 + "2") # TypeError: unsupported operand type(s) for +: 'int' and 'str'
   #+end_src
   #+begin_src python :results output :exports both :session *Python* :python python3 
     print(int("hello")) # ValueError: invalid literal for int() with base 10: 'hello'
   #+end_src
   
10) Name the three families of Python errors and when each strikes.
    #+begin_quote
    - /syntax/ errors: bad grammar - caught *before* the code runs
    - /runtime/ errors: a crash *during* execution, at the failing line
      (~NameError~, ~TypeError~, ~ZeroDivisionError~, ~IndexError~, ...)
    - /semantic/ errors: it runs and finishes, but the answer is wrong -
      no message at all
    #+end_quote
